# Companion service API and reliability

The versioned FastAPI implementation is `backend/reversecad/service.py`. Run the repository startup script. Its default is loopback port 8767; `--lan` exposes that port to the local network. The selected port avoids unrelated services already occupying 8765 and 8766 on the build Mac. `GET /v1/health` is public; every other operation requires `Authorization: Bearer <pairing token>`. A token identifies the paired owner of scans, jobs, and artifacts. Tokens are never included in error messages. The service uses SQLite WAL state and immutable capture directories under `REVERSECAD_DATA_DIR` (default `.reversecad-data`). Without an environment token it creates a private persistent `pairing-token` file; use the startup script's pairing instructions.

Capture assets are raw files, not archives. ZIP uploads have no extraction route and are rejected. `POST /v1/scans` creates or resumes an identifier; an omitted `project_id` retains the existing one. `GET /v1/scans/{scan_id}` returns uploaded file paths, SHA-256 digests, sizes, commit state, annotations, and reconstruction. `PUT /v1/scans/{scan_id}/assets/{relative_path}` requires `X-Content-SHA256`. A matching existing asset is idempotent; different content at an existing path is rejected. Retry only missing assets. `POST /v1/scans/{scan_id}/commit` validates every capture hash, frame contract, rigid pose, RGB dimensions and encoding, native depth stride/size, confidence and mask size, IDs, timestamps, and metadata. Interrupted captures may be committed with `complete:false`; missing files and inconsistent counts may not.

Raw observations stay immutable after commit. Annotations are separately versioned with `PUT /v1/scans/{scan_id}/annotations`; repeat identical content retains the revision. Crop and scale edits invalidate the fused reconstruction. Contact, manual measurement, attachment, and damage edits preserve the surface, with new evidence captured in the next job's immutable snapshot. Contact/crop coordinates refer to the corrected object-frame preview; they are not scaled a second time.

`POST /v1/scans/{scan_id}/reconstruction` accepts an optional JSON `request_id`. Repeating the same ID and evidence revision returns the same job. A reused ID with changed evidence is a conflict. `POST /v1/scans/{scan_id}/candidates` takes `family` and `attachment_method` and derives supported repair hypotheses from current reconstruction and annotations. Responses can include provisional candidates while status is `needs_input`; their questions and provenance remain visible.

`POST /v1/repairs` and `POST /v1/repairs/{repair_id}/revisions` accept `scan_id`, `family`, bounded numeric `parameters`, `attachment_method`, `mode` (`manual`, `fixture`, or `live`), `acknowledge_uncertainty`, optional `request_id`, and optional `candidate_id`. The service recomputes a selected candidate against current evidence and binds derived measurements server-side. Client-supplied extra measurements do not become observations. Live mode additionally requires `provider_consent:true` to send selected images/scan render to the configured provider. Only the server has the provider API credential.

Jobs are inspected with `GET /v1/jobs/{job_id}`. The submit response immediately includes `job_id`, `repair_id`, and reserved revision when applicable. States are queued, validating_input, reconstructing, planning, generating_cad, validating_cad, complete, needs_input, cancelled, and failed. `POST /v1/jobs/{job_id}/cancel` reaches the isolated process group and preserves committed capture data. Queued work survives restart; interrupted active work fails explicitly with `server_restarted` and can be retried. An idempotent submission never silently creates a second revision. Cancelled state cannot be overwritten by delayed worker progress or completion.

Each job runs trusted reconstruction/planning/CAD code in its own subprocess with CPU, wall-time, RSS, file-size and descriptor limits. The parent monitors process memory. Native filtered measurement points, not TSDF or RGB display refinement, supply CAD collision observations. Live proposal data never executes arbitrary Python or shell commands. Workers preserve input manifest/checksum/intent hashes, measurement sources, annotation revision, scan ID, repair ID and revision.

A valid CAD solid can still need measurements or an assembly check. Without explicit uncertainty acknowledgement, printable/source/coupon outputs are withheld and job status is `needs_input`; preview, parameters, intent and validation remain available. With acknowledgement, prototype artifacts may be downloaded while unresolved fit and `physical_fit:not_tested` remain explicit. `complete` requires verified files to exist. Inspecting a complete job rechecks artifacts and revokes success if an output is missing or corrupt. Downloads at `GET /v1/artifacts/{id}` validate the stored size and hash again and return `X-Content-SHA256`.

`DELETE /v1/projects/{id}` cancels that paired owner's jobs and removes that project's server scans, jobs and artifacts. It does not delete phone data or other projects.

Default budgets are 240 total persisted frame records, 512 MiB per capture, 128 MiB per asset, 1,600 assets per capture, 1 MiB per JSON API request and capture diagnostics, 240 seconds per worker and 4 GiB worker RSS. Schema files are in `schemas/*.v1.schema.json`; FastAPI exposes `/openapi.json`. Errors contain `error.code`, an actionable `error.message`, and a generated `request_id`. The `X-Request-ID` response header assists diagnosis without logging captured images or credentials.

Automated API/reliability checks are in `backend/tests/test_service.py`; actual isolated-worker RGB-D-to-CAD and export reimport checks are in `backend/tests/test_service_integration.py`. These validate software and synthetic observations. They do not establish iPhone sensing, dimensional sensor accuracy, printed fit, or attachment strength.
